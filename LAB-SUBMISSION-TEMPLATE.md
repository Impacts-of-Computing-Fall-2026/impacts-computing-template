## 1. What You Ran

Briefly describe what you did in the simulation — which buttons/modes you used, how many cycles or runs, and any settings you changed. A few sentences is enough; this section exists so the instructor can reproduce your results, not to pad length.

## 2. Raw Output

Paste the relevant numbers, log lines, or screenshots-as-text from the simulation here. Use a code block so formatting survives:


If a module's instructions ask for a specific figure (e.g. "record the Disparate Impact Ratio" or "note the cycle number where the alert triggers"), make sure that exact figure appears here, clearly labeled.

## 3. Analysis

This is the core of the submission — usually 300–600 words, though modules may specify otherwise. Address, at minimum:

- **What did the data show?** Describe the pattern in your own words, referencing the numbers from Section 2.
- **How does this connect to the week's theoretical framework?** Each module names specific thinkers and concepts (e.g. Illich's Second Watershed, Watters' behaviorist tracking, Innis's space/time bias). Use them explicitly — don't just gesture at "ethics" in general.
- **What's the real-world stakes?** Tie the simulation's toy example back to an actual system, platform, or policy it's modeling.

## 4. Reflection (1–2 sentences)

What surprised you, or what would you want to investigate further if you had more time? This is ungraded on content — it's here so the instructor can see where your thinking is heading.
